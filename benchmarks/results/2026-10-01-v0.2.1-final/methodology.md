All product files, existing five task definitions, wrapped prompts, grader, original submitted tests and acceptance checks stayed unchanged. Following the owner's explicit “Reprends”, a read-only account check confirmed allowance had reset; only the nine unattempted sessions resumed. Session 9 was never retried. The interrupted pair therefore cannot support a complete five-task headline aggregate. No README benchmark numbers were replaced.

This is deterministic bootstrap-fixture assembly and reviewed semantic transfer, not a paid autonomous bootstrap model evaluation. No previous measured AGENTS.md, solutions, conversations or frozen preparation records were reused. All 71 facets and safe-removal transfer validate, without requiring a bootstrap specification during normal work.

The evidence-only adapter retains the existing compact-series rule: `PROJECT_REFERENCE.md` is removed from Vanilla and excluded with AGENTS.md/CLAUDE.md from product-state equivalence hashing. Measurement code is untouched. No plugin is injected into either measured condition: this isolates generated repository guidance, not plugin installation, discovery, bootstrap cost or invoked Skill execution. The advisory Skill destinations remain verified against the tagged plugin.

Each of the 18 fixtures is a real Git repository with one untouched root commit, clean status, identical Git configuration, author identity, fixed timestamp and per-task commit message, no remotes, alternate objects, hooks or user/global Git config. Non-guidance tracked files and committed blob hashes match exactly within each pair; commit/tree hashes differ only because ContextLean tracks the three guidance files. Both conditions in each uninterrupted pair use the same temporary workspace path. ## Measurements

Codex input/cache/output/reasoning come from `turn.completed.usage`. Cached input is a subset of input; derived uncached = input − cached; total = input + output. Reasoning output is already included in output and never double-counted. No usage is fabricated for session 9. Command calls use unchanged unique `command_execution` IDs. Codex file reads and all-tool counts remain null.

Claude uses the unchanged prior bridge's final `result.usage` normalization: input = provider ordinary input + cache creation + cache read; cached = cache read; output = provider output. Thus derived uncached includes ordinary input and cache creation. Raw fields are retained to expose these distinct billing semantics. Commands are unique Bash tool-use IDs, including tool attempts; explicit Read calls and all explicit tool-use IDs are reliably counted, not unique files or shell-internal reads. No token comparison is made across models/providers. Wall time is local monotonic CLI-process duration, excluding setup, grading and publication. No provider cache flushing or service-load control was attempted.

A dated official ChatGPT standard-speed card, verified 2026-10-01, supports credit-equivalents for ChatGPT-authenticated Codex sessions with available usage. These are not account deductions or actual spend. Claude's reported `total_cost_usd` is retained as reported USD equivalent, not verified billing. Missing ninth-session usage makes complete campaign usage/cost unavailable. Known cost subtotals are labelled explicitly; no cross-currency conversion or pooled performance aggregate is made.

## Independent offline grading

After all 18 attempts, every saved solution is independently copied and regraded with the unchanged tagged grader. Submitted tests run first; the original five regression tests are restored in a separate evaluation copy; two independent acceptance checks run afterward. Each has a separate published log and explicit result. No model is invoked during grading. Success requires valid execution and usage, all three checks, preserved sample/guidance and untouched baseline HEAD. A passing partial solution from a failed execution is never counted as task success.

The supplied offline checker reconciles event-derived tokens/commands, every saved solution digest, prepared Git states, map/transfer receipts, prompt identity and checksums. `python3 verify_evidence.py --regrade` optionally reproduces all frozen grades without models. Normal reconciliation reuses already-passed offline grades bound to immutable hashes.

## Verification reuse and limitations

The visible trace review compares actual test identities/counts, discovery scope and intervening mutations, rather than “targeted/full” labels. Equivalent passed coverage with no visible relevant change/failure/unresolved result or project-required repeat is recorded as redundant; inaccessible identities or hidden state remain uncertain. Additional test cases, changed code/tests/config, initial failures and expanded acceptance scopes justify new verification. The review reports behavior, not assumed model intent or token causality.

Preliminary only: one observation per condition, a small synthetic Python fixture, tested configurations only. Stochastic behavior, provider cache and service conditions are uncontrolled. There is no statistical-confidence claim, causal performance attribution or universal token-savings claim. Unfavorable cases and the interrupted session are retained. Historical v0.2.0 batches are immutable and separate; the old invalid diagnostic batch is explicitly invalid for headline comparison. README headline replacement requires all 18 runs and grades to pass; that gate did not pass in this campaign.

Final Git patches are retained losslessly as `.patch.gz`: Git patch context lines contain a single space, which a repository whitespace checker otherwise mistakes for added trailing whitespace. No patch bytes or measurements were changed. [Compression records](patch-compression.json) bind the original bytes.
